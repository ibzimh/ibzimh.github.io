When I open a project I didn’t write, I try not to start at the top of the biggest file. I look at how it is run first: the readme if there is one, the scripts in the package file, the tests. Those tell me what the authors thought the program was for.

Then I find one real action and follow it from start to finish. If it is a web app, that might be a single button click. I read only the code on that path and ignore everything beside it. After a couple of these I usually have a rough map.

I skip configuration files, generated code and anything with a name like “utils” until I need it. I also skip the clever parts. They are rarely where the program’s main idea lives, and they make more sense once I know what they are in service of.

Last, I read the commit history for the parts that confuse me. A confusing line often has a message that explains it, written by someone who still remembered why.
