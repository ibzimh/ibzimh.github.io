I used to start every project by picking a framework. It felt like the responsible thing to do, the way you might buy a good toolbox before hanging a shelf. But I noticed that I spent the first week learning the toolbox and the second week working around it, and the shelf was still on the floor.

These days I begin with the smallest thing that could work. Usually that is one file and one command to run it. If it solves the problem, I stop there. If it doesn’t, I have learned exactly which part is missing, and that tells me what to add.

## Adding things on purpose

Nothing is off limits. A library, a build step or a database can all earn their place. The difference is that I let a real problem ask for them, instead of installing them in case a problem shows up. When one does arrive, I can judge the tool against something concrete.

## What it costs

It is not free. Sometimes I rewrite a piece I could have bought, and sometimes the small version stays small longer than it should. I accept that. A little code I understand is easier to change than a lot of code I don’t.
